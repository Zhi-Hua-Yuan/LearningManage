V1 原则：结构迁移与业务数据迁移分离。除经过审批的固定参考数据外，V1 不写入任何业务行、用户行、团队行、项目行、任务行、AI 日志或 Prompt 正文。

## 2. 播种决策

### 允许进入受控参考数据迁移的条件

- 数据是环境无关的固定字典或系统默认配置。
- 主键/编码稳定，重复执行可通过唯一键安全识别。
- 不含密码、Token、API Key、个人信息、业务文本或运行时生成时间。
- 已由产品和后端负责人确认所有权、版本和回滚方式。
- 有独立的校验 SQL，能验证数量、唯一键和关联完整性。

### 当前明确禁止

- 把主库 28 个用户、4 个团队、35 个项目、37 个里程碑、122 个任务、3 条周回顾或任何 AI 日志复制到 V1。
- 把 `prompt_template.template_content` 原文直接提交到 PR 1 或未审批的 PR 2。
- 为了填充 `user_role` 而猜测用户与 RBAC 角色映射。
- 在迁移中使用当前环境的 `CURRENT_TIMESTAMP` 作为固定参考数据的版本依据。

## 3. Prompt 模板六行分类流程

1. 仅在受控环境只读导出 `id/template_code/scene/version/enabled/is_delete` 元数据，不导出正文到日志。
2. 标记每行属于“正式默认模板、历史模板、环境专用模板、待确认”之一。
3. 只有“正式默认模板”可以进入后续受控播种文件；正文通过代码评审和敏感信息扫描。
4. 为每个正式模板定义稳定的业务编码、版本、启用状态和回滚行。
5. 在 PR 2 单独验收模板数量与唯一键，不与 V1 建表 DDL 混写。

本流程完成前，`prompt_template` 仅建表，不播种任何行。

## 4. 参考数据验收

- 空库迁移后，默认参考数据数量必须与批准清单一致；未批准表应为 0 行。
- 已有库接管后，业务行数和 RBAC 行数不得被迁移流程改变。
- 所有参考数据脚本可重复执行，且不依赖自增当前值或环境特定 ID。
- 审计日志只记录编码、版本和数量，不记录密码、Prompt 正文或其他敏感值。
