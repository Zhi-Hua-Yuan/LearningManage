# 阶段 0.3-B2 凭据轮换运行手册

状态：B1 生成，尚未授权执行  
原则：先增加新凭据并验证，再停用旧凭据；每类凭据独立设停止点

## 1. 执行前门禁

- B1 报告中的五项人工确认已完成。
- 当前 Git 工作区干净，阶段 0.3-A/B1 文档已评审。
- 最新数据库备份和恢复验证有效。
- 应用写入维护窗口已确认。
- 新凭据存储位置已经创建并限制访问。
- 终端和日志不会打印凭据正文。
- 旧凭据在新凭据验证前仍可用于回退。

任一条件不满足，停止执行。

## 2. MySQL 业务账号

推荐目标账号：`learning_manage_app@localhost`。实际 Host 必须根据应用连接来源确认，不能直接使用过宽的 `%`。

推荐业务权限：`SELECT, INSERT, UPDATE, DELETE ON learning_manage.*`。Flyway 后续使用独立迁移账号；业务账号不授予 `CREATE`、`ALTER`、`DROP` 或 `GRANT OPTION`。

执行顺序：

1. 在受保护会话生成新密码，禁止写入命令历史或仓库文件。
2. 创建业务账号并授予最小权限。
3. 用业务账号完成只读连接和关键表查询。
4. 在隔离环境验证必要写权限和逻辑删除行为。
5. 更新受控环境中的 `DB_USERNAME`、`DB_PASSWORD`。
6. 启动后端并验证核心接口。
7. 确认应用连接身份不再是 Root。
8. 观察无认证失败后，才进入 Root 密码轮换。

新账号默认认证插件与当前 JDBC 无 SSL 配置的兼容性必须先验证。不要为了快速兼容而扩大权限或降低认证强度。

## 3. JWT

1. 生成至少 32 字节的高熵随机密钥。
2. 将新值写入已确认的 Secret 存储，不写入 Git。
3. 确认所有后端实例能够同时取得相同值。
4. 在维护窗口更新并启动所有实例。
5. 旧 Token 请求受保护接口必须失败。
6. 重新登录获取新 Token，新 Token 必须成功。
7. 验证完成后销毁旧密钥的临时副本。

回退到旧密钥会让新 Token 失效，因此 JWT 回退同样需要通知重新登录。

## 4. Redis

当前 Redis 5.0.14 不支持 ACL。本次默认建议暂缓 Redis 认证变更，并单独选择以下路线之一：

- 升级到 Redis 6+，建立独立 ACL 用户；或
- 保持 Redis 5，通过持久化配置启用 `requirepass`，同时准备服务重启和旧配置回滚。

禁止仅执行临时 `CONFIG SET` 后就视为完成。无论选择哪条路线，都必须验证 AI 限流计数、过期时间和失败策略。

## 5. 阿里云 API Key

1. 用户在阿里云控制台创建新 Key。
2. 只记录 Key ID、创建时间和所有者，不记录正文。
3. 将新 Key 写入 Secret 存储并更新运行实例。
4. 经费用确认后执行一次最低成本真实调用。
5. 验证成功后停用旧 Key。
6. 再执行一次最低成本验证，确认没有实例仍依赖旧 Key。

无法创建或验证新 Key 时，不停用旧 Key。

## 6. MySQL Root

Root 只在业务账号稳定后轮换：

1. 确认后端、测试、脚本和备份任务均不再依赖 Root。
2. 在受保护会话生成新 Root 密码。
3. 修改 Root 密码并更新管理端 Secret。
4. 验证新的管理连接和备份命令。
5. 验证业务账号连接不受影响。
6. 清除旧密码的本机副本，但不修改 Git 历史。

## 7. 验证与停止条件

每次切换后验证健康检查、登录及新旧 Token、项目/任务/里程碑/周复盘/仪表盘、61 项测试、数据库行数和孤儿关联、Redis 限流（如处理 Redis）、AI 最低成本调用（获批后），以及 Git/日志/终端无敏感信息。

出现连接失败、影响实例不明确、权限不足或过宽、数据异常、日志泄密或新 Key 无法验证时，立即停止，不停用旧凭据。

## 8. 执行记录

B2 只记录凭据类型、供应商凭据 ID、创建/切换/验证/停用时间、负责人、存储位置名称、验证结果和回退状态。不得保存凭据正文、完整 Token 或可直接使用的环境文件。
