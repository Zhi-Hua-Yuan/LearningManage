# 阶段 0.3-B2-5 MySQL Root 密码轮换风险接受记录

决定日期：2026-08-19 Asia/Shanghai
目标实例：本机 MySQL `localhost:3306`
执行状态：本次不执行 Root 密码轮换
决定类型：本机范围内的残余风险接受

## 1. 用户决定

用户确认本机 MySQL Root 密码暂不更换，原因是当前运行范围仅限本机，应用已经切换到独立业务账号，当前没有将 Root 密码轮换作为本阶段必要动作。

本记录不代表 Root 密码已经轮换，也不代表该决定适用于云服务器、Docker、CI 或其他数据库实例。

## 2. 已验证前提

根据 B2-5.1 前门禁和后续 B2 记录：

- 当前 Root 账号为 `root@localhost`，没有确认到对外 Host 的 Root 账号。
- 应用使用 `learning_manage_app@localhost`。
- 测试使用独立的 `learning_manage_test_app@localhost`。
- 应用和测试连接不使用 Root。
- Root 密码没有进入应用环境变量。
- `MYSQL_ROOT_PASSWORD` 未作为应用配置使用。
- 当前范围为本机操作，不包含云服务器和 Docker 数据库。
- B2-4 完成后 8123、8124 端口已清理。
- 61 项自动化测试保持 0 failures / 0 errors。

## 3. 残余风险

旧 Root 密码曾存在于 Git 历史，并且本次没有轮换。因此，拥有本地仓库访问权限、同时能够连接本机 MySQL 的主体，理论上仍可能使用历史凭据获得 Root 权限。

当前风险被限定在本机范围，但不等于风险为零。Root 当前仍具有全局授权能力，认证插件仍为 B2-5.1 记录的现状；认证插件迁移也不在本次范围内。

## 4. 风险接受边界

本决定仅在以下条件持续成立时有效：

- MySQL 仅监听或允许本机访问；
- MySQL 端口不向局域网或公网开放；
- 应用和测试继续使用独立最小权限账号；
- Root 密码不在其他系统复用；
- 本机由可信用户使用；
- 不把当前本机配置直接复制到云端或生产环境。

## 5. 强制重新评审条件

发生以下任一情况时，必须重新评审并优先轮换 Root 密码：

1. MySQL 部署到服务器、Docker、CI 或其他机器。
2. MySQL 端口对局域网或公网开放。
3. 仓库对外共享、公开或交给其他不受信任的人员。
4. Root 密码在其他服务中复用。
5. 发生密码泄漏、主机入侵或安全事件。
6. 需要多人共同管理本机数据库。
7. 需要将本机环境作为生产或演示环境长期运行。
