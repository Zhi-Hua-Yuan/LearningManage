## 3. 发现和可能原因

### DQ-001：项目缺失用户

发现 1 条活跃项目记录，其 `user_id` 在 `user` 表中不存在。该项目没有关联任务、里程碑或 AI 重排记录，创建和更新时间均为 2026-04-11。

可能原因：用户曾被物理删除、历史数据导入不完整，或早期测试数据没有同步创建用户。

影响：项目所有权无法解析，后续权限校验、RAG 来源归属和项目统计都可能出现不确定结果。

### DQ-002：任务缺失项目

发现 2 条活跃任务和 1 条逻辑删除任务指向不存在的项目。三条任务的项目 ID 相同，创建时间集中在 2026-03-24 至 2026-03-25，用户仍然存在；没有对应的里程碑、AI 重排、状态幂等或改名日志。

可能原因：历史项目被物理删除、任务导入先于项目导入，或早期手工清理只删除了项目记录。

影响：任务无法归属项目，项目列表、任务查询、统计、后续权限和知识索引均可能产生错误。

## 4. 时间特征

RBAC 数据集中创建于 2026-04-15，租户数据创建于 2026-04-13；当前应用源码没有对应接入痕迹，说明它们很可能来自另一套初始化或历史模块。

孤儿任务集中创建于 2026-03-24～2026-03-25，早于 RBAC 表创建时间；孤儿项目创建于 2026-04-11。当前证据不足以证明这些记录来自同一批迁移。

## 5. 下游风险

- Flyway V1 可能遗漏数据库实际结构。
- 项目和任务权限无法可靠判断。
- 项目统计与任务统计可能出现数量不一致。
- 后续 Outbox、知识索引、RAG 和 Agent 可能处理无归属来源。
- 直接增加非空外键会在当前数据上失败。

## 6. 推荐修复

1. 先确认 RBAC 表所有权，不删除任何表。
2. 对 DQ-001 查询受控备份或业务记录，确认能否恢复原用户。
3. 对 DQ-002 查询历史备份，确认能否恢复原项目。
4. 无法恢复时，采用经过审批的逻辑删除或隔离策略。
5. 将上述关联完整性检查固化为 Testcontainers 和迁移前检查。
