## 非阻断观察

1. 团队周复盘分页 SQL 中的 `BINARY wr.visibility_scope = BINARY 'TEAM'` 不能被当前
   JSqlParser 正常解析，MyBatis Plus 每次记录 count 优化警告并退回低级 count SQL。
   当前查询结果正确；10,000 条数据下页面查询约 36.8 ms。
2. 已发布 Flyway 迁移在 MySQL 8.0.41 中多次触发 `BINARY expr` 弃用警告。迁移当前
   成功，但未来数据库大版本升级前需要验证替代写法或继续固定受支持版本。
3. 100,000 任务数据下，项目任务 Top 100 查询在 `ANALYZE TABLE` 后仍扫描全部
   100,000 行并耗时约 210 ms；逾期统计约 137 ms。原计划没有为这两个查询规定 SLO，
   因此暂未登记为缺陷。
4. AI 依赖健康状态按 30 秒刷新，Redis 容器恢复后在第二个刷新周期内才从
   `DEGRADED` 回到 `UP`。核心 readiness 始终为 `UP`。
5. `npm ci` 可以成功复现依赖，但 `@vue/test-utils → js-beautify → nopt/abbrev` 在固定的
   Node 22.13.1 上产生 `EBADENGINE` 警告；当前未启用 `engine-strict`，所以不阻断构建。

## 证据边界

- 没有确认 P0 不等于数学证明系统不存在 P0；本轮权限负向、周复盘隐私、RAG 来源权限
  和管理员接口均未发现数据泄漏。
- 前端 71 个操作的路径/方法全部匹配运行时 OpenAPI，但嵌套 DTO 没有由同一 Schema
  自动生成，仍依赖 TypeScript 测试、运行时归一化和高风险链路抽查。
- 后端缺少本轮生成的 JaCoCo 覆盖率；测试优先级依据现有 809+61 项测试、架构守卫和
  风险路径，而不是行覆盖率。
- 前端依赖漏洞的“存在”已确认，单条漏洞在当前浏览器构建中的可利用性未逐条武器化验证。
