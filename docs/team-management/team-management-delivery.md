# 团队管理全生命周期交付记录

## 需求与验收

- 所有登录用户可在 `/teams` 创建团队、通过邀请码加入团队，并查看所属团队与成员。
- OWNER 可管理邀请码、成员角色、所有权和团队解散；ADMIN 可编辑资料并移除 MEMBER；MEMBER 可查看并退出。
- 创建、加入、角色、退出、移除、转让和解散成功后，管理页与侧栏无需刷新即可同步。
- 仅不存在有效团队项目及团队共享周报的团队可解散。

## Review 结论

- 邀请码只对 OWNER 返回，前端仅保存在页面内存，不进入团队通用对象或浏览器存储。
- 所有权转让原子更新 `team.owner_id`、新 OWNER 和原 OWNER（降为 ADMIN）。
- 解散使用逻辑删除，保留 AI 派生与审计数据并依赖原有访问控制使其不可访问。
- 前端展示权限只改善交互，最终授权始终由后端重新校验。
- 本次复用现有字段，不需要数据库迁移。

## 验证与交接

- 后端：运行 `TeamLifecycleServiceImplTest`、`TeamLifecycleControllerTest` 及现有团队/项目/周报相关单元测试。
- 前端：运行 `npm run type-check`、`npm run test:ci`、`npm run contract:test`、`npm run build` 和 `npm run lint:ci`。
- 需要 MySQL 的集成/并发测试必须配置 `TEST_DB_USERNAME`、`TEST_DB_PASSWORD` 后执行完整 `mvnw test`。
- 回滚时前端可先移除 `/teams` 入口与新增 API 调用；后端新增接口为向后兼容扩展，无结构迁移需要回滚。
