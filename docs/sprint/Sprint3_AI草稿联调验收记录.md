# Sprint 3 AI 草稿联调验收记录

## 一、验收范围

本次验收覆盖 AI 任务拆解草稿的前后端闭环：

```text
输入学习目标
  -> 生成 AI 草稿
  -> 查看 / 刷新草稿详情
  -> 确认创建项目、阶段、任务
  -> 或取消草稿
```

接口契约见：[AI 草稿接口文档](../api/ai-draft-api.md)。

本记录只描述已完成的本地人工联调结果；不记录真实账号、JWT、AI Key、草稿 ID 或项目 ID 等敏感测试数据。

## 二、联调环境与前置条件

| 项目 | 说明 |
|---|---|
| 前端 | `learning-manage-frontend`，Vue 3 + TypeScript + Vite + Pinia + Axios + Tailwind CSS。 |
| 后端 | LearningManage，Spring Boot 3，Base URL 为 `http://localhost:8123/api`。 |
| 数据库 | MySQL，已执行项目、阶段、任务、AI 草稿、确认日志、调用记录和 Prompt 模板相关初始化脚本。 |
| 缓存 | Redis 已启动，AI 预览接口启用 `task-breakdown` 场景限流。 |
| AI 配置 | 本地环境已通过环境变量配置可用的 `ALIYUN_API_KEY`。 |
| 登录状态 | 使用独立测试账号完成登录，前端请求携带 JWT。 |

## 三、主流程验收结果

### 测试场景 3.1：生成 AI 草稿

- 请求：`POST /api/ai/breakdown/preview`
- 操作：在“AI 智能规划”页填写学习目标、周期、补充描述后提交生成。
- 预期结果：
  - 请求返回 `code=0`，并包含 `draftId`、`expireAt`、阶段及任务列表。
  - 前端进入对应草稿详情页。
  - 预览阶段不创建项目、阶段和任务。
  - 同一次用户操作只发起一次预览请求。
- 实际结果：接口成功返回草稿，详情页正常展示阶段、任务和有效期；未提前创建业务数据。
- 是否通过：通过。

### 测试场景 3.2：刷新后恢复草稿详情

- 请求：`GET /api/ai/draft/{draftId}`
- 操作：在草稿详情页刷新浏览器，或重新访问草稿详情路由。
- 预期结果：
  - 页面从服务端重新读取 `payloadJson`、`status`、`expireAt` 等信息。
  - 页面不依赖本地草稿缓存作为真实性来源。
- 实际结果：刷新后草稿内容、状态和操作按钮均可正常恢复。
- 是否通过：通过。

### 测试场景 3.3：取消草稿

- 请求：`POST /api/ai/draft/cancel`
- 操作：生成新的未确认草稿后点击取消，并刷新详情页。
- 预期结果：
  - 接口返回 `code=0`、`data=true`。
  - 草稿状态变为 `CANCELED(2)`，`canceledAt` 有值。
  - 已取消草稿不能再确认，且不会创建项目、阶段和任务。
- 实际结果：取消状态可持久化，刷新后仍展示“已取消”；未产生业务落库数据。
- 是否通过：通过。

### 测试场景 3.4：确认草稿并落库

- 请求：`POST /api/ai/breakdown/confirm`
- 操作：在预览中的任务拆解草稿详情页点击确认创建。
- 预期结果：
  - 请求携带 `draftId` 和客户端生成的 `operationId`。
  - 接口返回 `success=true`、`idempotentReplay=false` 和项目 `businessId`。
  - 服务端在同一业务流程中创建一个项目，以及草稿中对应的阶段和任务。
  - 草稿状态变为 `CONFIRMED(1)`，`confirmedAt` 有值。
  - 前端刷新项目/任务缓存后跳转至该项目的任务页面。
- 实际结果：项目、阶段和任务均成功创建；草稿确认状态、跳转及页面数据刷新正常。
- SQL 回查：
  - `ai_draft.status = 1`，且 `confirmed_at` 不为空。
  - `project` 仅新增一个对应项目。
  - `milestone` 和 `task` 的数量、关联关系与草稿内容一致。
  - `ai_draft_confirm_log` 写入确认记录并保存项目 ID。
- 是否通过：通过。

### 测试场景 3.5：重复确认幂等性

- 请求：重复提交相同的 `POST /api/ai/breakdown/confirm` 请求体。
- 操作：使用首次确认时的同一组 `draftId + operationId` 再次请求确认接口。
- 预期结果：
  - 接口返回 `success=true`、`idempotentReplay=true`。
  - 返回的 `businessId` 与首次确认一致。
  - 不重复创建项目、阶段、任务或确认日志。
- 实际结果：重复请求被识别为幂等回放，返回同一项目 ID，未生成重复业务数据。
- SQL 回查：同一用户、同一 `draftId + operationId` 在 `ai_draft_confirm_log` 中仅有一条记录。
- 是否通过：通过。

### 测试场景 3.6：草稿过期

- 请求：`GET /api/ai/draft/{draftId}`、`POST /api/ai/breakdown/confirm`
- 操作：对本地测试库中一条未确认草稿模拟超过 `expireAt` 后刷新详情页，并尝试确认。
- 预期结果：
  - 草稿状态更新为 `EXPIRED(3)`。
  - 前端展示“已过期”，确认和取消操作不可继续执行。
  - 确认接口不创建项目、阶段和任务。
- 实际结果：过期草稿正确进入终态，前端禁止继续确认，未产生新的业务落库数据。
- 是否通过：通过。

### 测试场景 3.7：Redis 限流

- 请求：连续调用 `POST /api/ai/breakdown/preview`。
- 操作：同一登录用户在 60 秒内连续发起超过 3 次任务拆解预览请求。
- 预期结果：
  - 前 3 次请求按正常流程处理。
  - 超出额度的请求返回业务码 `42900`。
  - 前端展示“请求过于频繁”提示，不自动连续重试。
  - 被限流的请求不创建 AI 草稿和 AI 调用记录。
- 实际结果：超过额度后正确返回 `42900`，前端提示正常；等待下一时间窗口后可恢复生成。
- 是否通过：通过。

## 四、调用记录与 Prompt 元数据核对

在成功生成任务拆解草稿后，核对 `ai_call_log`：

- 存在 `scene = task-breakdown` 的调用记录。
- 调用成功时状态为 `SUCCESS(1)`，并记录模型名称、耗时和重试次数。
- 调用记录包含 `prompt_type`、`prompt_template_id`、`prompt_version`、`prompt_source`。
- 内置 Prompt 的 `prompt_template_id` 可为空，`prompt_source` 为 `builtin`；数据库 Prompt 的来源为 `database`。
- 草稿详情、确认和取消不产生新的大模型调用记录。

核对结果：通过。

## 六、验收结论

本次 AI 草稿核心闭环已完成并通过本地人工联调验收：

1. 草稿生成、详情恢复、取消、确认落库、重复确认、过期和 Redis 限流均符合当前接口契约。
2. 草稿状态以服务端为准，确认请求通过 `operationId` 保证幂等。
3. 确认流程由后端统一创建项目、阶段和任务，前端不再逐条调用创建接口。
4. AI 调用记录与 Prompt 元数据可用于后续追踪模型、模板版本、耗时和失败原因。
5. E1～E6 异常场景已列入补测清单；在正式发布前应完成对应验证并回填本记录。
