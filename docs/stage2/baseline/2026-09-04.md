## 2. 当前代码事实

### AI 调用入口

- `AiInvocationPipeline.execute(...)` 已存在，职责包含 Prompt 解析、模型调用、响应处理和调用日志生命周期。
- `AiModelClient` 当前只有单轮文本接口：

```java
AiInvocationResult invoke(String primaryModel, String systemPrompt, String userPrompt);
```

- `AiModelClientImpl` 当前通过 OpenAI-compatible `/chat/completions` 发送 `system/user` 消息，只解析 `message.content`。
- `AiServiceImpl` 仍包含场景业务准备、Prompt 组装、直接模型调用、响应解析和部分正式写入逻辑。
- 当前代码清单发现 `AiServiceImpl` 仍有直接 `aiModelClient.invoke(...)` 调用点；完整清单见 [AI 调用清单](../ai-invocation-inventory.md)。

### 现有 AI 场景

```text
任务拆解预览 / 确认
周复盘润色预览 / 确认
今日任务排序
日报任务改名
清单任务重排预览 / 确认 / 取消
兼容旧版任务拆解和周复盘润色
```

### 当前数据与能力缺口

- `ai_call_log` 尚未保存 requested model、finish reason、provider request ID、Prompt Token、Completion Token、总 Token、价格版本、估算成本、Trace ID 和脱敏状态。
- `ai_draft` 尚未保存 Schema 版本和 Trace ID。
- `ai_draft_confirm_log` 当前唯一约束是 `(user_id, draft_id, operation_id)`，需要在 V3 前审计并迁移为草稿级唯一。
- 当前失败枚举已覆盖配置、超时、网络、限流、上游错误、非法响应和内部错误，但尚未区分协议错误、场景解析错误、业务校验错误和降级结果。
- 当前 AI 日志包含请求/响应正文，阶段 2 必须先脱敏、再截断，并记录正文哈希。
