# ADR-002：周复盘可见性与团队共享

状态：`ACCEPTED`

日期：2026-08-23

## 背景

当前 `weekly_review` 只有作者、周快照、`reflection` 和 `next_plan`，没有可见范围、共享目标或稳定资源关联。仅增加 `visibility_scope=TEAM` 仍无法判断共享给哪个团队；复用私人正文作为团队内容会直接破坏后续 RAG 权限隔离。

## 决策

1. 增加 `visibility_scope`，只允许 `PRIVATE`、`TEAM`。
2. 增加 `team_id` 作为 TEAM 模式的唯一共享目标。
3. 增加 `shared_summary`，由作者独立填写；不得由接口自动复制私人正文。
4. 增加 `focus_project_id`，原 `focus_project_name` 保留为历史快照。
5. 增加 `weekly_review_task` 保存多任务关联。
6. TEAM 模式首版仅支持共享给一个团队，且关联项目和任务必须属于该团队。
7. 作者读取完整 VO；团队成员读取独立共享 VO。团队角色不授予私人正文权限。
8. 存量记录全部回填为 PRIVATE，不生成共享摘要或团队关联。

## 数据不变量

```text
PRIVATE → team_id IS NULL
TEAM    → team_id IS NOT NULL AND shared_summary 非空
```

跨表成员关系、项目归属和任务归属由应用事务校验；数据库仅约束枚举值、唯一关系和必要索引。

## 生命周期

- 作者退出团队后仍保有完整作者视图。
- 团队当前有效成员可以读取已经发布的共享摘要。
- 作者退出后不能继续以该团队为目标保存 TEAM 状态，但可以改为 PRIVATE 或删除。
- 复盘改为 PRIVATE 或删除后，团队共享查询立即不可见；阶段 4 再负责索引删除事件。

## 备选方案

### 不保存 `team_id`，从关联任务推断团队

拒绝。任务可能来自多个项目或为空，推断结果不稳定且存在跨团队泄漏风险。

### 直接向团队返回 `reflection`

拒绝。私人正文与共享内容无法独立撤回、索引或评测。

### 使用 `weekly_review_share` 支持多团队多摘要

首版延期。该模型更通用，但会增加 UI、唯一性、撤回和 RAG 权限组合复杂度。阶段 1 明确限制一份周复盘只定向一个团队；需要多团队发布时新增 ADR 和迁移。

## 影响

- Controller 不再直接接收或返回 `WeeklyReview` 实体。
- TEAM 保存需要团队成员、项目和任务批量校验。
- 共享 VO 从类型层面排除私人字段。
- API 和前端必须明确提示“完整正文不会共享”。

## 验收

- 私人正文越权返回数为 0；
- TEAM 记录没有 `team_id` 或共享摘要时不能落库；
- 跨团队任务不能关联到 TEAM 复盘；
- 存量复盘全部为 PRIVATE。
