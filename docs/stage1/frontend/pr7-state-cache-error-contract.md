# PR7 状态、缓存与错误处理合同

状态：`FROZEN（WP7-A 已合并）`

日期：2026-08-31

## 1. 状态来源

| 数据 | 权威来源 | 前端保存策略 |
|---|---|---|
| 当前用户 | `/user/me` | 会话级状态 |
| 个人项目 | `/project/list` | 保持现有短期缓存 |
| 团队及角色 | `/team/my` | 会话级内存 |
| 团队项目 | `/project/team/list` | 会话级内存，按 teamId |
| 团队成员 | `/team/{teamId}/members` | 会话级内存，按需加载 |
| 任务和 capability | `/task/list` | 个人项目可短期缓存；团队项目默认内存或按用户隔离；当前打开任务从最新列表结果替换 |
| 分配历史 | assignment-history | 当前面板内存，不持久化 |
| 团队共享复盘 | `/review/team` | 当前页面内存，不持久化 |

## 2. 敏感状态限制

- 团队成员、分配历史、共享摘要不得写入未按用户隔离的 localStorage；
- 团队任务若使用持久缓存，key 必须包含当前用户 ID 和项目 ID；首版推荐只用内存；
- 不缓存私人复盘正文的网络响应副本；现有编辑表单仅保存在当前页面内存；
- capability 不得跨用户会话复用；
- 日志不得打印私人正文、共享摘要、完整 reason、Token 或完整 API 响应。

## 3. 缓存失效

### 分配、转派或解除成功

```text
清理当前项目任务缓存
→ 清理聚合任务缓存
→ 重新读取任务列表并替换当前打开任务
→ 重新读取 capability
→ 刷新打开中的分配历史
```

仅在本地改 `assigneeUserId` 不合格，因为任务双方的 capability 可能同时变化。

### 状态或内容变更成功

- 使用服务端响应更新最小状态；
- 随后刷新受影响任务或项目范围；
- 状态接口以 `finalStatus/completedAt` 为准；
- 任务重组后清理里程碑和项目进度相关缓存。

### 团队或权限变化

- `/team/my` 不再包含当前团队时，删除其项目、成员和任务内存状态；
- 当前路由失权时跳转到仍可访问的个人任务页；
- 页面重新获得焦点且存在打开的任务时刷新当前项目任务列表，并以对应返回项替换旧任务；
- 写操作收到 `40300/40400/50001` 时不得继续使用旧 capability 或成员选项。

### 会话结束

主动登出、`40100`、Token 清除或当前用户变化时清理：

```text
个人/团队项目缓存
任务与聚合任务缓存
团队和成员内存状态
分配历史
共享复盘
AI pending 中包含业务 ID 的会话状态
```

## 4. 错误状态机

| 场景 | 前端处理 |
|---|---|
| 业务码 `40000` | 保留表单，显示安全业务消息或字段提示 |
| 业务码 `40100` | 清理会话和受保护缓存，跳转登录 |
| 业务码 `40300` | 不按登录失效处理；提示权限变化并刷新资源 |
| 业务码 `40400` | 提示资源不存在/已失效，关闭详情并刷新列表 |
| 业务码 `50001` | 撤销乐观状态，刷新任务/成员后要求重新确认 |
| HTTP 401 | 按会话失效处理 |
| HTTP 403 | 按网关/运行时响应区分；不得无条件把稳定业务 `40300` 当作 401 |
| 超时/断网 | 保留未提交表单，允许安全重试 |
| `changed=false` | 幂等成功，不重复生成本地历史或成功副作用 |

## 5. 并发流程

负责人变更：

```text
打开对话框时记录 current assignee
→ 提交 assigneeUserId + 显式 expectedAssigneeUserId
→ 提交中冻结控件
→ 成功后全量刷新任务事实
→ 50001 时保留用户选择但刷新当前负责人并要求重新确认
```

状态变更：

```text
生成 clientRequestId + 记录 expectedStatus
→ 提交中禁止第二个不同目标状态
→ 网络重试复用同一个 clientRequestId
→ 使用 finalStatus 结束乐观状态
```

周复盘：

- 保存期间冻结可见性、团队和关联选择；
- TEAM 保存失败时保留私人正文和计划；
- 团队失权后不得自动降级提交 PRIVATE，必须由用户确认新的可见性；
- 后端返回的可读关联始终覆盖本地旧关联事实。
