## 1. 目标

PR7 将 PR3～PR6 已交付的团队权限、任务负责人、分配历史和周复盘隐私能力接入前端。后端仍是授权和数据事实的唯一权威；前端负责提供正确、可理解且不会泄漏私人字段的交互。

PR7 的核心链路为：

```text
进入个人或团队项目
→ 按 TaskVO.capabilities 渲染任务操作
→ OWNER/ADMIN 创建、分配或转派任务
→ 成员在允许范围内更新自己的任务
→ 查看负责人变更历史
→ 作者保存 PRIVATE 或 TEAM 周复盘
→ TEAM 当前成员只读取共享摘要
```

## 2. 纳入范围

1. 我的团队、团队项目和团队成员的只读上下文；
2. 团队项目导航；
3. 任务创建时选择负责人；
4. 展示创建人、当前负责人、最近分配人和分配时间；
5. 按五项 `TaskVO.capabilities` 控制任务操作；
6. 分配、转派和解除分配；
7. 分页读取负责人变更历史；
8. 状态变更改用独立幂等接口；
9. PRIVATE/TEAM 周复盘编辑；
10. 共享团队、共享摘要、重点项目和任务关联；
11. 团队共享复盘列表；
12. 缓存失效、失权刷新和并发冲突处理；
13. 前端契约、组件测试、回归测试和验收证据。

## 3. 不纳入范围

- 不新增或修改后端业务接口；
- 不修改已发布 V1/V2 Flyway migration；
- 不实现完整团队管理页面、OWNER 转让或角色管理改版；
- 不在 PR7 调用成员主动退出或管理员移除接口；这两条后端链路由 PR8 全栈验收继续覆盖；
- 不全量重构 `TaskList.vue`、`WeeklyReview.vue` 或 `BasicLayout.vue`；只抽取本阶段触达的局部组件；
- 不引入 Playwright 等新的端到端基础设施；
- 不引入 Qdrant、Embedding、RAG、Agent 或 Redis 权限缓存。

## 5. 前端结构约束

建议新增的边界：

```text
src/types/                 API 和页面共享类型
src/api/team.ts            团队只读上下文 API
src/stores/collaboration.ts 当前用户、团队、团队项目、成员的内存状态
src/components/task/       负责人选择、分配对话框、历史面板
src/components/review/     可见性、关联选择、团队共享卡片
```
